# Signed Wrapper Implementation Note

Updated: 2026-07-22

## Goal

Build a first signed int8 baseline for the current unsigned approximate 8x8 multipliers in `FPGA_multiplier/approx_unsigned8x8`.

This baseline is:

```text
signed int8 a,b
  -> mag_a = abs(a), mag_b = abs(b)
  -> unsigned approx88_cascade(mag_a, mag_b)
  -> restore sign with sign(a) xor sign(b)
```

It is a precision/behavior baseline. It is not yet proof that the final signed RTL has the best area-delay trade-off.

## Correctness Checks

1. Exact unsigned core check:
   - `build_signed_wrapper_lut(exact_unsigned8_lut())` exactly equals standard signed int8 multiplication for all `a,b in [-128,127]`.
   - Boundary cases include `-128`, `-1`, `0`, and `127`.

2. Candidate Verilog simulation check:
   - The unsigned LUT is generated by directly simulating the original `final_best_approx88_cascade.v`.
   - Simulated `error_cases`, `ER`, `MED`, and `WCE` are checked against the original candidate JSON metrics.
   - `MRED` is reported but not used as a hard check because scripts may define relative-error denominators differently.

3. RTL wrapper equivalence check:
   - `signed_approx88_wrapper.v` was simulated for all 65536 signed int8 input pairs.
   - Candidates 17, 20, and 10 all match their generated Python signed LUT exactly.

Commands used:

```powershell
python tests\smoke_test_signed_wrapper.py
python scripts\generate_fpga_signed_wrapper_luts.py --candidates 17 20 10
python scripts\verify_signed_wrapper_rtl.py --candidates 17 20 10
python scripts\run_fpga_signed_wrapper_report.py
```

## Current Signed Product-Level Results

From `outputs/reports/fpga_signed_wrapper_product_report.md`:

| candidate | error_rate | MAE | RMSE | max_abs | relative L2 |
|---|---:|---:|---:|---:|---:|
| cand10 | 0.690918 | 116.681 | 205.509 | 930 | 0.037629 |
| cand17 | 0.745605 | 87.916 | 148.601 | 880 | 0.027209 |
| cand20 | 0.740479 | 116.821 | 206.425 | 930 | 0.037796 |

Interpretation:

- Candidate 17 is still the best average-error option under this signed-wrapper baseline.
- Candidate 10 has lower error rate but larger average magnitude error than candidate 17.
- Candidate 20 remains useful as a low-resource candidate, but its signed product-level MAE is close to candidate 10.

## What This Does Not Prove Yet

- It does not prove the signed wrapper has acceptable hardware overhead.
- It does not prove a future signed-aware retrained multiplier will have the same outputs.
- It does not prove W8A8 GEMM or model-level accuracy is acceptable.

Next experiment should connect these signed-wrapper LUTs to GEMM-level tests, then compare with TCASI24 LSAM1/CSAM2 under the same distributions.
